## 战马闹钟 — 闹钟不响第二轮修复（4个致命Bug）

### 问题现象
用户反馈设定的闹钟还是不响。经诊断发现4个新的致命Bug。

### 修复的Bug
1. **res/raw/ 目录为空，没有声音文件**：代码引用 `RawResourceAndroidNotificationSound('alarm_sound')` 但 res/raw/ 下无文件 → Android 静音。修复：添加 `alarm_sound.ogg`
2. **通知声只响一次（最核心）**：`flutter_local_notifications` 只弹一条通知，声音几秒就结束。修复：新增 `AlarmRingingService.kt`（Android Foreground Service），MediaPlayer 循环播放 + Vibrator 循环震动，通过 MethodChannel `com.example.alarm_clock/alarm_ring` 的 `startAlarmRing`/`stopAlarmRing` 控制
3. **震动模式全0**：`vibrationPattern: Int64List(4)` = [0,0,0,0] 无震动。修复：改为 `Int64List.fromList([0, 500, 200, 500])`
4. **Android 14 fullScreenIntent 权限不给**：小米14默认不授予 USE_FULL_SCREEN_INTENT。修复：设置页添加"锁屏闹钟提醒"引导，点击跳转系统设置

### 修改的文件
- **新建 `AlarmRingingService.kt`**：Foreground Service，MediaPlayer looping + Vibrator 循环
- **修改 `MainActivity.kt`**：注册 `alarm_ring` MethodChannel + `openFullScreenIntentSettings`
- **修改 `alarm_notification_service.dart`**：添加 `startAlarmRing()`/`stopAlarmRing()` 静态方法；`showAlarmNotification` 调用 `startAlarmRing()`；`cancelAlarmNotification`/`cancelAll` 调用 `stopAlarmRing()`；背景通知处理器也处理了 start/stop；添加 `snoozeAlarm` 方法（5分钟后重新调度）；修复 vibrationPattern
- **修改 `alarm_fullscreen_screen.dart`**：`_dismiss()` 和 `_snooze()` 都调用 `stopAlarmRing()`；添加贪睡按钮
- **修改 `AndroidManifest.xml`**：注册 `AlarmRingingService`，foregroundServiceType="specialUse"
- **添加 `res/raw/alarm_sound.ogg`**：闹钟声音文件
- **修改 `settings_screen.dart`**：添加"锁屏闹钟提醒"权限引导入口

### 技术决策
- 使用 Foreground Service 而非仅依赖通知声音，确保闹钟持续响铃
- MediaPlayer 使用 USAGE_ALARM 音频属性，Doze 模式下也能响
- Vibrator 兼容 Android 12+ VibratorManager 和旧版 Vibrator
- 贪睡功能：5分钟后重新调度通知

## 战马闹钟 — 第三轮修复：通知消失+无法关闭

### 问题现象
闹钟能响了，但通知显示一会就自动消失，之后无法点击关闭闹钟。

### 根因分析
`flutter_local_notifications` 的 `zonedSchedule` 到时间后由 Android 系统自动弹通知，**Flutter 侧没有任何回调被触发**。因此 `startAlarmRing()` 永远不会执行，闹钟只响一次通知声就结束。通知消失后用户也无法关闭。

### 修复方案
用原生 Android `AlarmManager` 替代 `flutter_local_notifications` 的 `zonedSchedule` 来调度闹钟触发时间：

1. **新建 `AlarmScheduler.kt`**：MethodChannel `com.example.alarm_clock/alarm_scheduler`，提供 `scheduleExactAlarm`/`cancelExactAlarm` 方法，直接调用 AlarmManager 精确定时
2. **新建 `AlarmReceiver.kt`**：BroadcastReceiver，接收 AlarmManager 广播，到时间后直接启动 `AlarmRingingService`
3. **修改 `AlarmRingingService.kt`**：
   - 通知渠道改为 `IMPORTANCE_HIGH`（之前是 LOW，通知可能被系统收回）
   - 添加 `fullScreenIntent` 和 `setOngoing(true)` + `setAutoCancel(false)`，通知不可滑动关闭
   - 从 intent extras 读取 alarmId/title/body
   - 关闭时也取消 flutter_local_notifications 的通知
4. **修改 `alarm_notification_service.dart`**：
   - `scheduleAlarmNotification` 改为优先通过原生 AlarmManager 调度，zonedSchedule 作为兜底
   - `cancelAlarmNotification` 同时取消 AlarmManager 定时和 flutter_local_notifications 通知
5. **修改 `MainActivity.kt`**：
   - 注册 `AlarmScheduler` MethodChannel
   - 从闹钟通知/全屏 Intent 启动时通知 Flutter 显示全屏页面
6. **修改 `AndroidManifest.xml`**：注册 `AlarmReceiver`
7. **修改 `main.dart`**：监听 `com.example.alarm_clock/alarm_fire` MethodChannel，原生端通知 Flutter 显示全屏闹钟页面

### 技术决策
- 原生 AlarmManager 替代 zonedSchedule：因为 zonedSchedule 只弹通知，不回调 Flutter
- AlarmRingingService 的通知改为 HIGH importance + ongoing + fullScreenIntent：确保通知不可被系统自动消失
- 保留 zonedSchedule 作为 fallback：万一 AlarmManager 不可用

## 战马闹钟 — 第四轮：页面动画+铃声选择+电池权限弹窗

### 修复的3个问题

1. **页面切换动画从左到右**：`pushNamed('/alarm_ringing')` 用了默认的 MaterialPageRoute 滑动动画。修复：改为 `PageRouteBuilder` + `FadeTransition` 淡入动画（300ms），`_routeToAlarmScreen` 和 `alarm_fire` MethodChannel 两处都改了

2. **铃声选择功能**：原来只有4个假铃声名（默认/日出/海浪/鸟鸣），不生效。修复为完整铃声系统：
   - **Kotlin端**：新增 `com.example.alarm_clock/ringtone` MethodChannel，提供 `getSystemRingtones`（从 RingtoneManager 查询 TYPE_ALARM + TYPE_NOTIFICATION + TYPE_RINGTONE）和 `pickCustomAudio`（ACTION_OPEN_DOCUMENT audio/*，支持 SAF 选择本地音乐，takePersistableUriPermission 保持权限）
   - **Flutter端**：`add_edit_alarm_screen.dart` 重写铃声选择为底部弹窗，分组显示"默认/系统铃声/自定义"，支持从文件选择
   - **数据模型**：`AlarmInfo` 新增 `ringtoneTitle` 字段，`ringtone` 从简单名称改为 URI 格式（`default` / `content://...`）
   - **数据库**：版本从2升到3，添加 `ringtoneTitle` 列，迁移旧 `ringtone='默认'` 为 `'default'`
   - **播放链路**：ringtoneUri 从 Flutter → AlarmScheduler → AlarmReceiver → AlarmRingingService，MediaPlayer 根据 URI 决定播放内置声音还是系统铃声/自定义音频
   - **设置页**：铃声设置也改为使用系统铃声列表

3. **电池优化权限反复弹窗**：`requestIgnoreBatteryOptimizations()` 每次启动都调用 `AndroidIntent` 打开系统弹窗。修复：Kotlin 端新增 `isIgnoringBatteryOptimizations` 方法（用 PowerManager 检查），Flutter 端先检查已有权限，只有未授权时才弹窗

### 修改的文件
- `lib/main.dart`：alarm_fire channel 改为 FadeTransition + import AlarmFullScreenScreen
- `lib/services/alarm_notification_service.dart`：_routeToAlarmScreen 改淡入动画 + startAlarmRing 接受 ringtoneUri 参数 + requestIgnoreBatteryOptimizations 先检查权限 + import AlarmFullScreenScreen + _ringtoneToSound 更新
- `lib/models/alarm_info.dart`：新增 RingtoneInfo 类 + AlarmInfo 新增 ringtoneTitle 字段
- `lib/services/alarm_storage_service.dart`：数据库 v2→v3，添加 ringtoneTitle 列
- `lib/screens/add_edit_alarm_screen.dart`：重写铃声选择为底部弹窗+系统铃声+自定义音频
- `lib/screens/settings_screen.dart`：铃声设置改用系统铃声列表
- `android/.../MainActivity.kt`：新增 ringtone channel + isIgnoringBatteryOptimizations + startAlarmRing 传 ringtoneUri
- `android/.../AlarmRingingService.kt`：支持 URI 播放（default→内置，content://→系统/自定义），新增 currentRingtoneUri 字段
- `android/.../AlarmReceiver.kt`：传递 ringtoneUri 到 AlarmRingingService
- `android/.../AlarmScheduler.kt`：scheduleExactAlarm 传递 ringtoneUri
